## 三、开发过程中的主要设计取舍

这部分记录**哪些地方是人工判断、改变了 AI 给出的初版方案**——它是「这是一次真实的产品设计过程、而非一键生成」的直接证据。

### 1. 三通道简化为两档
AI 初版方案给出「试用 / 快问 / 深议」三通道。经评估认为对用户过于复杂，**合并为「快速分析」与「决策记录」两档**：
- 快速分析：不要求预先建立员工档案，说明情况即可获得多角度分析
- 决策记录：完整流程（关联画像 → 写初判 → 分析 → 拍板 → 回访 → 复盘）

代码体现：`shared/model.ts` 中 `channelLabels` 与 `migrateDecision()` 保留了对早期 `trial` 通道的兼容迁移。

### 2. 否决「分步向导」式首页
AI 初版按"先设置 → 再建档 → 再决策"组织界面。被明确否决：

> 做决策是实时性的事，打开就要能输入问题。

最终首页设计为：**上部约七成描述问题，下部填写自己的初步决定，中间一条分隔线**——不做步骤跳转。

### 3. 初判从「门禁」改为「开关」
原方案要求：不写初步打算就不能获得分析。经讨论发现这**把两件不该绑定的事绑在了一起**：

| | 独立方案调用 | 风险提示调用 |
|---|---|---|
| 是否需要初判 | 不需要（它本来就是独立的） | 必须（它的输入就是初判） |

于是改为：
- **有初判** → 两次调用 → 独立方案 + 风险提示 + 并排对比
- **无初判** → 只做独立方案，并在界面明确告知「本次没有风险提醒」

**价值**：新用户不被第一道门槛卡住；填写初判变成「奖励」而非「惩罚」。

### 4. 撤回「反向采样」机制
AI 初版设计了「每 5 次强制注入一个用户大概率排斥的角度」来防止回声室效应。经论证后**撤回**：

理由——该机制依赖「系统会学习用户偏好」这一前提，而本产品**不回流数据、不按偏好排序生成、只修改用户可见可改的画像**，因此系统级回声室的来源已被消除。强行注入反向角度会让 AI 显得刻意抬杠，损害参谋的专业感。

**改为「复盘镜子」**：不干预任何一次分析的生成，只在复盘页如实陈述事实（如「这次你采纳了温和调整，没有动差异较大的方案」）。实现成本接近零，但保住了「我们记得你过去怎么选」这一差异点。

### 5. 角度差异化「写进结构，不写进提示词」
原方案在提示词里写「请给三个不同角度」。经判断这在提示词层面**做不到**——模型极容易给出三个措辞不同、实质相同的方案（如「当面聊 / 私下聊 / 单独谈」）。

改为**结构强制 + 服务端校验**：
1. 固定角度类型枚举：`人事安排 / 流程规则 / 节奏时机 / 资源投入 / 对外沟通 / 暂不动作`
2. 要求本次输出的角度类型两两不同
3. 服务端解析后校验 `angleType` 是否重复 → 重复则自动重试一次 → 仍重复则**如实标注不伪造**
4. `暂不动作` 永远是一个合法选项（对治模型「总想让你做点什么」的偏差）

代码体现：`shared/model.ts` 的 `angleTypes`、`qualityFlagsSchema`。

## 五、当前版本明确不做的事

这些边界写进了产品设计，也是答辩时的主动说明：

1. **不接入任何办公 IM / OA 系统**——不是能力不足，是设计原则。进群即公开、进系统即留痕，产品核心价值会当场消失。
2. **不做员工评分、排名、能力雷达图。**
3. **不自动推断结果，不替用户拍板，不预选「最佳方案」。**
4. **不把用户内容用于训练；不做任何形式的用户间数据分享。**
