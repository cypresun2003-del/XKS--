## 一、本仓库的说明

本仓库为「第二视角」项目的参赛代码仓库，**已对主办方开放全部访问权限**。

主办方在提交要求中承诺：

> 我们保证尊重选手原创版权、不剽窃内容/思路，仅评审用。

我们据此**选择不隐藏任何核心内容**，理由如下：

| 内容 | 处理方式 | 理由 |
|---|---|---|
| 全部源码（含模型调用与提示词） | **公开** | 技术实现是本项目参赛的核心展示内容，隐藏会使评审无法核实 |
| 设计文档（`docs/`） | **公开** | 记录从需求到实现的设计过程，是原创性的直接证据 |
| 测试用例（`tests/`） | **公开** | 便于主办方验证代码可运行 |
| 本机账户绝对路径 | 已脱敏 | 涉及个人设备信息，与项目本身无关 |

**我们不做任何内容隐藏**，全部内容可核查。

本项目于 **2026 年 10 月 2 日 16:08（北京时间）从零开始**，开发过程使用 AI 编程工具辅助。

详细的开发时间线、工具使用方式、关键设计取舍，见 [`开发历程.md`](./开发历程.md)。

可用于核验原创性的证据分级清单，见 [`赛期证据清单.md`](./赛期证据清单.md)。

**需主动说明的一点**：本仓库的 Git 提交历史**始于 10 月 3 日**，晚于实际开发起始时间。原因是开发早期使用了 AI 编程工具直接生成文件，**未同步建立版本控制**。这是本项目开发流程上的缺陷，我们如实说明，并提供以下替代证据：

1. **AI 编程工具的会话记录**（由工具自动生成、逐条带毫秒级时间戳、用户无法事后编辑单条历史）
2. **文件系统时间戳**（呈现 10-03 全天分批推进的修改时间）
3. **界面截图演进**（`artifacts/` 中两张截图相隔约 13.5 小时，界面明显不同）
4. **设计文档链**（记录设计被推翻与修改的过程，而非仅最终结论）

自 10 月 3 日 Git 建立后，所有改动均通过版本控制记录。

## 三、项目边界（主动声明）

本项目在设计上明确不做以下事项，这既是对用户隐私的保护，也避免被误读为就业决策工具：

1. **不接入任何办公 IM / OA 系统**——不是能力不足，是设计原则。一旦接入即留痕，产品核心价值将消失。
2. **不做员工评分、排名、能力雷达图。**
3. **不自动推断结果，不替用户拍板，不预选「最佳方案」。**
4. **不把用户内容用于训练；不做任何形式的用户间数据分享。**

此外，模型调用层对以下行为做了服务端强制约束（非提示词层面的"建议"）：
- 禁止输出任何人事裁决类建议（换人、调岗、裁员等），由正则与服务端校验双重拦截
- 要求三个角度的类型两两不同，校验失败自动重试，仍失败则**如实报错而非伪造结果**
- 员工画像的更新建议必须逐字回溯用户原文，无依据则该次分析作废
