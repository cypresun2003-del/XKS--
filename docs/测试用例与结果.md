## 三、重点验证的三个机制

这套测试不只是功能验证，其中三项直接对应产品的核心机制——**如果这三条不成立，产品逻辑本身就不成立**：

**① 独立视角的物理隔离（用例 1、5）**

验证的是：用户写下的初步判断**真的没有被送进生成独立视角的那次请求**。这保证了 AI 给出的三个角度是独立产生的，而不是顺着用户思路做的补充。

**② 角度差异化的结构约束（用例 4）**

验证的是：服务端确实在检查角度类型是否重复，重复时会重试，**重试仍失败就拒绝保存——不会伪造一个"看起来成功"的结果**。

**③ 判断权始终在用户手里（用例 2、11、16）**

验证的是：AI 不能替用户拍板；「觉得有帮助」不会被记成「已经采纳」；复盘时 AI 提出的画像调整建议也不会自动生效。

## 四、其他测试工具

除上述自动化测试外，仓库内还有三个辅助检查工具：

| 文件 | 用途 | 说明 |
|---|---|---|
| `tests/ui-server.ts` + `tests/ui-check.cjs` | 界面自动化检查 | 启动一个**只使用内存数据与固定响应**的隔离服务（4318 端口），**不读取任何正式数据** |
| `tests/live-smoke.ts` | 真实接口连通性检查 | 手动执行，只读取本机连接配置并发送虚构案例，**不读写业务记录**；运行时消耗模型额度 |
| `tests/model-production-check.ts`、`tests/compare-models.ts` | 模型输出质量对比 | 用于比较不同模型/配置下的输出差异，辅助提示词调优 |

## 五、如何复现

```bash
npm ci              # 安装依赖
npm run typecheck   # 类型检查
npm test            # 运行测试套件
```

测试**不依赖外部模型服务**（使用固定的模拟响应），因此无需配置 API Key 即可完整复现。
