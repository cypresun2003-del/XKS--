# 第二视角 - 第二视角

独立运行的 AI Agent 决策参谋。打开首页即可写问题；员工画像按需关联，自己的初步决定必须先写，之后 AI 才会提供三个独立角度。员工档案、决策和复盘记录保存在本机。

## 启动

需要 Node.js 24 或更高版本。

双击本目录的 **start.cmd**，等待启动完成，在浏览器打开 **http://127.0.0.1:4317**。使用期间保持启动窗口运行，结束后按 Ctrl+C。

也可以运行：

    npm ci
    npm run build
    npm start

开发时使用 npm run dev。检查使用 npm run build 和 npm test。

## 第一次使用

1. 首次打开会看到带高亮和指向箭头的 8 步短引导，可随时跳过；问题区右上角的问号可以重新查看。员工画像可以不选。
2. 先写问题，再写自己的初步决定。初判是分析前的必填项，不会发送给生成三个独立方案的 AI 请求；如已连接 AI，系统会另行检查这条初判的风险。
3. 分析前核对本次发送资料并明确同意。AI 的三个方案与用户初判分别展示，最终采用哪种安排由用户确认。
4. 需要保留最终决定并跟进结果时，在分析页确认安排；可设置回访时间。任务完成后记录实际结果和事后看法，AI 提出的画像变化建议仍需逐条确认。
5. “用户信息”可填写昵称、行业和一句日常决策介绍；“设置”依次提供外观、备份与恢复、清空本机业务记录，底部提供反馈邮箱和简短隐私说明。

## 当前界面

- 左侧为分离的浮动入口：圆形“用户信息”，以及圆角矩形的“员工画像”“决策库”“设置”。
- 右侧为一个始终保留的大框，上部“你遇到了什么问题？”用于描述情况，下部“你打算怎么做？”填写自己的初步决定，中间只有一条分隔线。员工关联在上部左下角，分析按钮在下部右下角。
- 四个入口及决策详情均以覆盖弹窗打开。点右上角叉号或按 Esc 关闭后，主工作区保留当前输入；保存中的确认操作会暂时阻止关闭。
- 两套主题同时改变整个画布、输入框、按钮、弹窗与重点卡片，选择在当前浏览器中保留。
- Logo 采用双层线条造型，颜色随主题切换。
- 员工画像支持命名分组，同一员工可以属于多个分组。关联时可逐人多选、勾选分组或全选当前员工；勾选分组等同批量勾选其中的当前员工，取消分组则取消其中这些员工，其他分组的选中状态随名单同步。每次分析最多关联 100 人。归档成员不参与新关联，分组变动不会改写已经选定或保存的名单。
- 决策库采用紧凑横条，显示状态、决策名、关联员工、更新日期和编辑/删除操作，删除需要再次确认。
- 反馈邮箱为 cypresun2003@gmail.com。邮件入口只打开用户的邮件程序，不自动发送，也不会附带决策内容。

## 核心流程

首页的轻量流程合并了原快速入口：直接描述问题，不需要预先建立员工档案；有关联画像时可以选择使用。每次分析都要求先写初步决定，避免 AI 先影响用户判断。

决策记录支持确认最终安排、回访和事后复盘。早期版本创建的快速分析记录仍可查看，也可以补充资料继续使用；员工画像仍为可选。

AI 连接由产品维护者配置，用户界面不提供模型地址、模型名或密钥输入。服务不可用时仍可保存资料、草稿、自己的最终决定及实际反馈，并可通过反馈邮箱联系支持。应用不会用模拟内容冒充真实分析。模型调用费用由所配置的账户承担。

## 数据与边界

- 本地服务仅监听 127.0.0.1。员工、决策、历史与连接配置存于 data/zhujian.sqlite；密钥不回传页面、不包含在业务备份中。数据库文件并未加密，请妥善保护电脑账户和磁盘。
- 已保存的记录不会因关闭浏览器或重启服务而清空。首页尚未点击“分析”的输入只保留在当前页面，刷新或关闭页面会丢失；覆盖弹窗不会清空这些输入。进入决策记录后，编辑约 1 秒自动保存，请确认“已保存”再关闭；意外断电可能丢失最后尚未保存的修改。
- 分析前展示将发送的业务内容。云端服务商会处理这些内容，其留存规则以服务商政策为准。本应用不承诺云端零留存。
- 不设置真实姓名与公司名称字段。可以检测并替换常见手机号和邮箱，但无法保证识别所有真实姓名、公司名或其他敏感信息；请自行核对并使用代号。
- “设置”可导出第 3 版 JSON 业务备份，包含员工分组。支持导入第 1、2 版旧备份，缺少分组时按空分组恢复。整库恢复会替换业务记录；操作前先导出备份。模型连接配置不会被业务备份替换。
- 员工归档不移除历史引用。删除决策不会撤销已经确认的画像变化。清空业务数据保留模型连接配置；移除密钥请使用单独的按钮。
- 当前版本面向一位本机用户，没有远程用户登录和跨设备隔离。后续公开给评委访问前需增加认证、独立数据空间、调用额度和 HTTPS 部署。

## 开发结构

- src/：React 页面与交互。
- server/：本地 Express 接口、SQLite、真实模型调用及输入校验。
- shared/：共享数据类型与验证规则。
- tests/：关键工作流程、确认边界与失败保护测试。

补充检查：tests/ui-server.ts 是仅使用内存数据和固定测试响应的隔离服务（4318 端口），不读取正式资料；tests/ui-check.cjs 配合 Playwright 与 Edge 验证界面、主题、引导和决策闭环。可用 PLAYWRIGHT_MODULE 指定已安装的 playwright-core 路径。tests/live-smoke.ts 是手动执行的真实接口检查，只读取本机连接配置并发送虚构案例，不读取或写入业务记录，运行会使用模型额度。

产品维护者可复制 .env.example 为 .env 配置接口；已有本机数据库中的连接配置优先于环境变量，并在本次升级中保留。原本机维护接口仍保留，但没有普通用户入口。更换服务商地址时必须重新填写对应密钥，以免将旧密钥发送给另一服务商；这些本机维护能力不可直接作为公开部署的管理接口。

## 本地端口

默认端口为 4317。需要修改时，在 .env 中配置 PORT 并访问对应端口。使用 ZHUJIAN_DATA_DIR 可以指定其他数据目录。
